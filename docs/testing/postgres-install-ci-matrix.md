### Wymagane adresy testowe i izolacja

- Backend Jest i testy migracji wymagają jawnego `POSTGRES_TEST_URL`; brak zmiennej kończy się błędem, nie pominięciem testu (`tests/postgresTestEnvironment.cjs:12-25`, `tests/migrations/helpers.ts:28-39`). Test URL musi być PostgreSQL na dozwolonym lokalnym hoście, a nazwa DB kończyć się `_test` lub `_test_db` (`tests/postgresTestEnvironment.cjs:17-28`, `tests/migrations/helpers.ts:28-45`). Nie ustawiaj tu danych produkcyjnych.
- Playwright wymaga `PLAYWRIGHT_DATABASE_URL`; konfiguracja fail-fast jest w `playwright.config.ts:4-12`. `tests/playwright/postgresServer.cjs:13-18` waliduje URL, przygotowuje izolowany schemat, uruchamia migracje i uruchamia serwer dla E2E (`:43-76`). `tests/playwright/isolatedPostgres.cjs:12-20,45-89` również buduje izolowany schemat.
- Harnessy tworzą i sprzątają izolowane schematy. Test restore roundtrip tworzy i usuwa dedykowaną bazę testową; używa hostowych `pg_dump` i `pg_restore` (`tests/migrations/restoreRoundtrip.test.ts:30-34,57-80,126-162`). To może być pominięte (`it.skip`), gdy binaria nie są dostępne (`:30-34`).
- Lokalny kontener testowy można przygotować według `docker-compose.postgres-test.yml:1-14`; wymaga `POSTGRES_TEST_PASSWORD` i domyślnie publikuje port wyłącznie na `127.0.0.1:55432`. **UNKNOWN:** nie potwierdzono, czy host użytkownika ma Docker ani czy ten Compose został uruchomiony.

# Draft autosave: limit 200 MB (localStorage + IndexedDB)

Data: 2026-10-30
Status: WDROŻONE (kod + testy), commit oczekuje na zgodę

## Problem (FACT)

`DRAFT_MAX_BYTES = 4 000 000` (`public/js/shared/draftStore.js`). Oferty ponad ~4 MB
nie miały kopii roboczej — toast „Draft zbyt duży — NIE zostanie zapisany; chroń się
jawnym zapisem (Ctrl+S)". Zmierzone w tej sesji na `localhost:3000` (Chromium):
`localStorage.setItem` przyjmuje 32 MB, przy 50 MB rzuca `QuotaExceededError`.
Podniesienie samej stałej do 200 MB nic nie daje: zamiast `oversize` byłby `quota`.

## Decyzja

Dwa backendy, wybór po rozmiarze koperty:

- `size <= DRAFT_SYNC_MAX_BYTES` (4 MB) → `localStorage`, zapis synchroniczny
  (pewny także w `pagehide`, gdzie async IDB może nie zdążyć).
- `size > DRAFT_SYNC_MAX_BYTES` → IndexedDB (`sok_drafts` / `drafts`),
  cap `DRAFT_MAX_BYTES = 200 MB`, zapis asynchroniczny (`res.write`).
- Brak IndexedDB → `{ok:false, reason:'oversize'}` (bez cichego zapisu lokalnego).

## Dowód runtime (Chromium, `localhost:3000`)

- 4.1 MB → `route: idb`, `localStorage` pusty, odczyt `ok` (4200 pozycji), lista 1, `removeDraft` → `missing`.
- 20.5 MB → `idb`, odczyt `ok` (21000 pozycji); mały draft (10 poz.) → `local`, lista pokazuje oba, cleanup → 0.
- Recovery: 5.2 MB draft w IDB → `draftAutosave.checkRecovery('offer_studnie')` otwiera modal „Znaleziono niezapisany draft".
- Pulpit: kafelek „1 szkic", popup pokazuje wiersz „Oferta (Rury) · #probe-resume … 5200 pozycji" (draft tylko w IDB).

## Ryzyka / granice

- `pagehide`: duży draft zapisuje się asynchronicznie — może nie dojść. Bez zmian względem
  stanu sprzed zmiany (wcześniej nie zapisywał się wcale).
- IDB bez limitu 200 MB w kodzie przeglądarki: cap egzekwuje `draftStore` (rozmiar JSON).
- L2 (kopia serwerowa) nadal 256 KB — duże drafty są tylko lokalne.
- `_draftRemoveIfDead` (self-heal przy zapisie) sprawdza tylko `localStorage`; dla dużych
  draftów rolę tę pełni `_draftCheckRecovery`.

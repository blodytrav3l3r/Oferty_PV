## 3. Cztery warunki P0.0 (wszystkie łącznie)

1. **Zod bez zmian kontraktu:** spisz które schematy walidują wejście a które zapisane; `null`/`0`/decimale/historyczne zachowują znaczenie; brak rozszerzania na API/zapis bez uzasadnienia.
2. **RED z właściwego powodu:** FAIL = konkretny defekt (np. ujemny PATCH, ciche `0`, `12,5` odrzucone); po fix PASS; test zielony przed zmianą odrzucony.
3. **Ledger rozłączny:** `applied+locked+unsupported+rejected == total`; kategorie rozłączne; odrzucone i błędy parsowania jawnie rozliczone; zero zniknięć/podwójnego liczenia.
4. **Checkpoint bez cudzych zmian:** hash bazowy + status + wyniki przed + lista plików + kontrakty; commit tylko własne/kompletne/bezpieczne; brak wymuszania commita i czyszczenia worktree.

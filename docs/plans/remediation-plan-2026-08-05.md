## 4. Ryzyka i mitigacje

| Ryzyko                                                                           | Mitigacja                                                                                                                                                                                                                                              |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `escapeHtml` użyty dwukrotnie (podwójne zakodowanie `&amp;lt;`)                  | Przy naprawie XSS sprawdzić, czy wartość nie jest już escapowana przez caller; testy wizualne wydruku po zmianie                                                                                                                                       |
| Usunięcie „martwego" kodu, który jest wywoływany przez `onclick` w HTML (string) | Przed usunięciem zawsze `grep` po całym repo (w tym `*.html`) — wymóg w każdej pozycji fali 2                                                                                                                                                          |
| Rate-limit in-memory nie działa przy wielu instancjach / restarcie               | Świadoma decyzja (ponytail: limiter in-memory wystarcza dla single-instance SQLite; przy skalowaniu — redis/DB w osobnej iteracji)                                                                                                                     |
| `git rm --cached` usunie plik z repo innych deweloperów                          | `local_catalog.db` i `scripts/archive/` nie są używane przez aplikację (potwierdzone: `tsconfig.json:26` wyklucza `scripts/archive`); wpis w CHANGELOG/docs przy release                                                                               |
| Usunięcie `esbuild` zepsuje build frontendu                                      | ~~Vite ma własny esbuild (bundlowany); weryfikacja `npm run build:frontend` w fali 6.3~~ → **potwierdzone jako ryzyko realne (deeb32a):** Vite 8 NIE ma własnego esbuild — to _optional peer dep_; usunięcie faktycznie psuje build.
